# terraform-provider-authlete 3.0.0

Manage [Authlete](https://www.authlete.com) services and OAuth 2.0 / OpenID
Connect clients with Terraform.

> [!WARNING]
> This is a beta release. Please report any issue you run into.

## Requirements

- Terraform 1.0 or later
- An Authlete 3.0 account and an **Organization Token** from the console

### Compatibility

| Provider | Authlete API |
|---|---|
| 3.x | 3.0 |
| 1.3.x | 2.2 and later |

The 3.x line is generated from the Authlete 3.0 API description and does not
work against a 2.x server. It is not an upgrade of 1.3.x: list attributes that
were sets are now ordered lists, and `attributes` is an attribute rather than a
block, so configuration and state both need changing. Nothing upgrades into it
by accident, because a `~> 1.3` constraint excludes it.

The major was aligned with the API once, at 3.0.0. After that the provider
versions on its own changes, so a later major does not imply a new Authlete
API. This table is what states the mapping.

## Installation

Copy this into your Terraform configuration, then run `terraform init`.

```hcl
terraform {
  required_providers {
    authlete = {
      source = "authlete/authlete"
      # Pin the release you want. The current one is on the registry page:
      # https://registry.terraform.io/providers/authlete/authlete/latest
    }
  }
}

provider "authlete" {
  # An Organization Token from the Authlete console. Creating a service requires
  # one; a Service Access Token is scoped to a single existing service and
  # cannot create another.
  #
  # Prefer the environment variable. A token written here ends up in version
  # control.
  # bearer = "..." # or set AUTHLETE_TOKEN

  # Your regional cluster. Defaults to https://us.authlete.com.
  server_url = "https://us.authlete.com" # or set AUTHLETE_SERVER_URL

  # Dedicated Cloud and On-Premise deployments only. Shared Cloud uses
  # Authlete's own IdP and needs nothing here.
  # idp_host = "authlete-login.example.com" # or set AUTHLETE_IDP_HOST

  # For a self-managed deployment behind a proxy or a private CA.
  # http_headers    = { "X-Example" = "value" }
  # tls_skip_verify = false
}
```

## Usage

The installation block above configures the provider. Describe a service and
the clients that belong to it:

```terraform
resource "authlete_service" "example" {
  service_name = "My API"
  issuer       = "https://auth.example.com"

  supported_grant_types    = ["AUTHORIZATION_CODE", "REFRESH_TOKEN"]
  supported_response_types = ["CODE"]
}

resource "authlete_client" "web" {
  service_id    = tostring(authlete_service.example.api_key)
  client_name   = "Web application"
  client_type   = "CONFIDENTIAL"
  redirect_uris = ["https://app.example.com/callback"]
}
```

Then run `terraform apply`.

Anything you leave out takes Authlete's default. A service does not need every
setting listed to work, and omitting one is not the same as setting it empty.

## Provider configuration

| Attribute | Environment variable | Required | Notes |
|---|---|---|---|
| `bearer` | `AUTHLETE_TOKEN` | yes | An Organization Token. See [Authentication](#authentication). |
| `server_url` | `AUTHLETE_SERVER_URL` | no | Your cluster. Defaults to `https://us.authlete.com`. |
| `organization_id` | `AUTHLETE_ORGANIZATION_ID` | to create a service | The organization services are created under. |
| `idp_host` | `AUTHLETE_IDP_HOST` | Dedicated Cloud and On-Premise | Your own identity server. |
| `api_server_id` | `AUTHLETE_API_SERVER_ID` | Dedicated Cloud and On-Premise | The cluster ID, shown in the console. Derived automatically for the public clusters. |
| `http_headers` | | no | Extra headers, for a proxy. |
| `tls_skip_verify` | | no | Disables certificate verification. Only against a deployment you control. |

Provider configuration wins over the environment.

## Authentication

The Authlete console issues two kinds of token, and which one you need depends
on what your configuration does.

| Token | Scope | Can do |
|---|---|---|
| **Organization Token** | the whole organization | Everything, including creating and deleting services. |
| **Service Access Token** | one existing service | That service and the clients inside it. **Cannot create or delete a service.** |

**Use an Organization Token unless you have a reason not to.** Creating and
deleting a service goes through Authlete's identity server rather than your
cluster, and that endpoint accepts only an Organization Token. Any configuration
with an `authlete_service` resource in it will hit this on the first apply.

A Service Access Token is enough when the service already exists and Terraform
only manages what is inside it, for example a configuration that holds
`authlete_client` resources and refers to the service by id.

If you supply a token that cannot do what the configuration asks, the provider
says which kind is required rather than returning a bare 401.

## Deployment types

Shared Cloud needs nothing beyond a token, a `server_url` and an
`organization_id`. Dedicated Cloud and On-Premise also need `idp_host` and
`api_server_id`, because creating and deleting a service goes through an
identity server the provider cannot guess.

## Removing a setting from your configuration

Deleting an attribute from your configuration means you no longer have an
opinion about it, not that it should return to its default. The value stays as
you last set it.

To clear something, set it explicitly:

```terraform
supported_displays = []   # supports none
description        = ""   # empty
```

This is standard Terraform rather than anything specific to Authlete, but it
catches people out. The one exception is the mutually exclusive certificate
subject types, `tls_client_auth_subject_dn` and the four
`tls_client_auth_san_*` attributes: Authlete accepts exactly one, so naming a
different one clears the previous one for you.
